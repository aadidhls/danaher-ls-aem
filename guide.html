What We've Built

A running record of what's been built across our sites — features, integrations, apps, and anything else worth sharing — kept here so any opco can see what already exists and how it works.

Key Capabilities:

  • Filter and select products for publishing/unpublishing.
  • Submit requests and monitor their progress in the processing queue.
  • Track rules and workflows (e.g., Adobe I/O Runtime or equivalent).
  • Trigger manual overrides outside the normal schedule.
  • Review and audit request history for transparency and compliance.

Built as a reusable, repurposable Edge Delivery Services (EDS) block — one implementation that any opco can drop onto a page and re-theme, instead of a one-off build.

At a glance

Filters & Product List for finding SKUs · Manifest Details & Response Log to submit a request · Product Bus Queue & Runtime Rules to check what's pending · Manual Override for an instant publish run · Request History logged locally per user. Full walkthrough of each panel is in the linked guide below.

Per-opco styling
All accent colors in the block resolve from three CSS variables — --pt-primary-color, --pt-primary-dark, and --pt-primary-light — set once in publisher-tool-src.css. Each opco keeps its own copy of that stylesheet with its own brand values, so re-skinning the console for a new site is a three-variable swap, not a rebuild.
Data source
The product/catalog feed the console reads from isn't hardcoded — it's exposed as an authorable field in the block's properties panel in Universal Editor. Authors can point the block at a different data source per page or per opco without touching code.

A new EDS block that lets shoppers filter every product in a category — pulled live from PIM and Coveo — by facets like Process Step, Brand, or Product Class. Authors can add, remove, or reconfigure which facets appear directly in the block, matched to any facetable field in Coveo, with no rollout required.

Facet configuration
Facets are defined in a placeholder JSON file, not hardcoded, so an author can add or remove a facet by editing that file — no developer or deployment needed.
Data source
Product data comes from PIM, indexed and served through Coveo. The Family ID and which facets to show are authorable fields in the block's properties panel in Universal Editor.

Extends the existing PDP hero block with a discontinued-state banner, so a product's lifecycle status is authorable alongside the rest of the hero content rather than needing a separate block or manual page edit.

SEO-safe fallback
Discontinuing a product no longer means losing the page. It stays indexable and simply reframes itself around what to do next, instead of returning a 404.
Smart "View alternatives" CTA
If PIM has a replacement product set on the discontinued item's attribute, the CTA links straight to that alternate product. If not, it falls back to Talk to an Expert. Both the banner text and the link destinations are managed in config, not hardcoded.
